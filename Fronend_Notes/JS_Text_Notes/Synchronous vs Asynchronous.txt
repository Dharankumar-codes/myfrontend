🚀 Callback Function

A Callback Function is a function that is passed as an argument to another function and is executed only after a particular task is completed. JavaScript is a single-threaded language, which means it can execute only one statement at a time. However, some operations such as API calls, database operations, file reading, and timers take time to complete. Instead of stopping the entire application and waiting, JavaScript continues executing other code and calls the callback function when the operation is finished. This mechanism helps handle asynchronous operations efficiently. Although callbacks solve asynchronous problems, excessive nesting of callbacks can make code difficult to read and maintain, leading to a problem called Callback Hell.

Example
const orderFood = (callback)=>{

   console.log("Order Received");

   setTimeout(()=>{

      console.log("Food Prepared");

      callback();

   },3000);

};

const delivery = ()=>{

   console.log("Food Delivered");

};

orderFood(delivery);
🚀 Callback Hell
Callback Hell occurs when multiple asynchronous operations depend on each other and callbacks are nested inside callbacks repeatedly. As the application grows, the code becomes deeply indented, difficult to understand, difficult to debug, and harder to maintain. Developers often struggle to trace errors and understand the execution flow. This problem was one of the major reasons why Promises were introduced into JavaScript. Callback Hell does not necessarily break the application, but it significantly reduces code readability and maintainability.

Example
login(()=>{

   profile(()=>{

      orders(()=>{

         payment(()=>{

            console.log("Completed");

         });

      });

   });

});
🚀 Promise
A Promise is an object that represents the eventual completion or failure of an asynchronous operation. Instead of passing callback functions repeatedly, Promises provide a cleaner and more structured way to handle asynchronous code. A Promise can exist in one of three states: Pending, Fulfilled, or Rejected. When an operation succeeds, the Promise is resolved using resolve(). When it fails, it is rejected using reject(). Promises make code easier to read and help eliminate Callback Hell by allowing developers to chain asynchronous operations using .then() and .catch() methods.

Example
const orderFood = ()=>{

   return new Promise(

      (resolve,reject)=>{

         setTimeout(()=>{

            resolve("Food Prepared");

         },3000);

      }

   );

};

orderFood()

.then(data=>{

   console.log(data);

});
🚀 then()
The then() method is used to handle successful Promise execution. When a Promise is resolved using resolve(), the data passed to resolve becomes available inside the then() method. Multiple then() methods can be chained together to perform a sequence of asynchronous operations. This makes code cleaner and more organized compared to nested callbacks. In modern JavaScript applications, then() is commonly used for handling API responses, database results, and asynchronous workflows.

Example
promise

.then(data=>{

   console.log(data);

});
🚀 catch()
The catch() method is used to handle errors that occur during Promise execution. If a Promise is rejected using reject(), the error is automatically passed to the catch() block. This provides centralized error handling and prevents application crashes caused by unhandled asynchronous errors. Using catch() improves application stability and user experience by allowing developers to display meaningful error messages.

Example
promise

.catch(error=>{

   console.log(error);

});
🚀 Async Function
The async keyword is used to declare an asynchronous function. When a function is marked as async, JavaScript automatically wraps its return value inside a Promise. Async functions were introduced to make asynchronous programming easier and more readable. They allow developers to write asynchronous code that looks and behaves like synchronous code. This significantly improves code readability and reduces the complexity associated with Promise chains.

Example
const getData = async()=>{

   return "Hello";

};
🚀 Await Keyword
The await keyword can only be used inside an async function. It pauses the execution of the current function until the Promise is resolved or rejected. Unlike callbacks and Promise chains, await makes asynchronous code appear synchronous and easier to understand. JavaScript does not block the entire application when using await; it only pauses the execution inside that specific async function while allowing other operations to continue.

Example
const getData = async()=>{

   const result =

   await orderFood();

   console.log(result);

};
🚀 Async/Await
Async/Await is a modern syntax built on top of Promises that simplifies asynchronous programming. Instead of chaining multiple .then() methods, developers can use await to wait for asynchronous operations in a clean and readable manner. Async/Await improves code maintainability, reduces nesting, and makes debugging easier. Today, most modern JavaScript applications, React projects, Node.js applications, and APIs use Async/Await for handling asynchronous operations.

Example
const getFood = async()=>{

   const result =

   await orderFood();

   console.log(result);

};

getFood();
🚀 Fetch API
The Fetch API is a built-in browser function used to communicate with external servers and APIs. It allows JavaScript applications to send HTTP requests and receive data from a backend server. Fetch returns a Promise, which means it can be handled using .then() or Async/Await. In modern web development, Fetch is widely used for retrieving users, products, orders, authentication data, and other information from APIs. It enables dynamic web applications that can update content without reloading the entire page.

Example
fetch(

'https://jsonplaceholder.typicode.com/users'

)

.then(response=>{

   return response.json();

})

.then(data=>{

   console.log(data);

});
🚀 API (Application Programming Interface)
An API is a communication bridge between the frontend and backend. It allows different software systems to exchange information using predefined rules. When a user performs an action such as logging in, viewing products, or placing an order, the frontend sends a request to the API. The API processes the request, interacts with the database if necessary, and returns the response back to the frontend. APIs are the backbone of modern web applications because they enable data sharing between client applications and servers.

🚀 Fetch Using Async/Await
Using Async/Await with Fetch is the most popular approach in modern JavaScript applications. It makes API calls easy to read and understand. First, the application waits for the server response using await fetch(). Then it converts the response into JavaScript objects using response.json(). Finally, the received data is displayed in the UI. This approach is widely used in React, Node.js, Next.js, and MERN Stack applications.
